# 在文章里展示红石结构和运行状态

一段录制可以在多处正文中引用。每张插图都有自己的初始镜头和事件书签。插图接近视口时自动渲染 3D 模型，初始停在文章书签或录制起点。配置了封面时，加载期间先显示封面。

## 在游戏中录制

在运行 MicroTimingReplay 的 Java 版游戏里创建一个独立的录制。用两个角点圈住输入、线路以及需要观察的装置，再触发开关。例如，下面的命令录制 200 个游戏刻。把示例坐标替换为电路的实际范围。

```text
/mtr profile create lamp
/mtr profile area add lamp 100 64 100 106 69 105
/mtr record lamp 200
```

触发电路后等录制结束，也可以执行 `/mtr record stop`。对于现有 profile，MTR 再次开始录制时会追加事件。单独录制一次完整动作最容易和文章对照。

## 导出并试播

在博客仓库根目录运行下面的命令，将第一个路径换成你实际的录制目录。1.21.10 分支通常写到 `config/mtr/<存档标识>/<录制名>/`，导出器读取其中的 `record.dat` 和 `profile.dat`。前者是起始世界快照，后者包含按游戏刻组织的事件。原始录制可以放在仓库外。

```powershell
npm run mc:export -- "D:\录制\lamp" "assets/minecraft/lamp/scene.json" --minecraft 1.21.10
npm run dev
```

浏览器打开 [本地 lamp 预览](http://localhost:4173/preview/minecraft/lamp/)即可看到模型和时间轴。这个地址由本地预览服务器提供，导出后就可以试播，文章可以稍后再写。变更配置后刷新页面即可。新的导出需要选用空的输出路径，以保留旧场景的书签和封面。

导出器按本项目使用的 MicroTimingReplay **Java 版 1.21.10** 录制格式编写，内置这个版本的原版方块状态表。改变方块注册表的模组需要加上 `--registry "路径/reports/blocks.json"`，提供与录制环境一致的状态表。其他游戏版本还需要录制格式兼容。对于跨维度录制，可以加上 `--dimension minecraft:overworld` 选择一个维度。同一维度内的多个选区会合并。

## 设置文章书签

在本地预览里逐步前进到想讲解的事件，旋转模型选好角度，点击「复制书签配置」。在 `scene.json` 末尾的 `bookmarks` 对象中新增一个名称，将复制的对象作为它的值。第 0 步代表录制起点，第 1 步代表第一个事件执行后。界面显示世界坐标，配置中的 `focus` 使用相对于 `origin` 的方块坐标。

```json
"bookmarks": {
  "lamp-update": {
    "step": 2,
    "focus": [1, 0, 0]
  }
}
```

上面的步数和方块位置仅用来说明格式，以实际录制为准。复制出的 `camera` 可一起保留。要用封面，将图片放在 `scene.json` 旁，在书签中加入 `"poster": "lamp-update.webp"`。场景顶层的 `poster` 可作为所有书签的默认封面。保存后，打开 [带书签的本地预览](http://localhost:4173/preview/minecraft/lamp/?bookmark=lamp-update) 可检查落点。

## 在 Markdown 中引用

文章放在 `content/posts/`，分类填写 `Minecraft`。正文中使用以下围栏。省略 `bookmark` 时从录制起点打开。

````markdown
```mc-scene
scene: lamp
bookmark: lamp-update
caption: 红石灯收到邻居更新。再前进一步，观察灯的 lit 属性。
```
````

运行 `npm run build` 生成文章页。正式文章会检查场景、书签和本地资源是否存在。标记为 `draft: true` 的文章可以提前写好围栏，等录制完成再发布。

默认播放速度是 **20 GT/s**，即每秒 20 个游戏刻。想让某张插图慢放，在它的 `mc-scene` 围栏里加一行 `speed: 5`。想让同一录制在多篇文章里都使用这个速度，可以在 `scene.json` 顶层写 `"playbackSpeed": 5`。围栏中的设置优先。读者也可以在播放器里临时改速，或将选定的速度保存为自己在这个浏览器中的默认值。已保存的个人偏好优先于文章设置。

只展示静态投影时，在场景目录放入投影文件，并将 `scene.json` 写成 `{"version":1,"schematic":"door.litematic"}`，正文沿用同一语法。

静态投影和运行回放默认启用 XeKr 的 **XK Redstone Display 26.3.0**。红石粉上的数字随信号强度变化，未覆盖的资源沿用原版。文章直接引用原有场景即可。[作者发布页](https://modrinth.com/resourcepack/xk-redstone-display)。

## 回放中可以核对什么

- 宽屏时事件树立在 3D 视图右侧、没有底框，游戏刻的编号在每一行最右端，事件直接从树干分叉；刻度尺竖在树的左边（上端第一刻、下端最后一刻）；游戏刻读数、播放按钮、设置和两个链接收在视图左下角的控制条里。窄屏时它们排在模型下方，刻度尺横向。3D 视图没有底色，透出文章背景。滑条以游戏刻为单位。拖到没有事件的刻时，时刻显示继续前进，模型保持最近一次变化后的状态。新版导出器保留录制开头和结尾的空刻；旧场景缺少范围时，以已记录的事件确定起止刻。
- 播放速度和显示粒度收在控制条的一行摘要里，点设置图标会浮出一张设置卡，点卡外或按 Esc 关闭。列表可连续滚动；滚离当前行时，列表边缘会出现「当前 · 第 N 刻」，点一下回到当前行。显示粒度有「游戏刻」「阶段」「事件」三档，默认是「阶段」；它也决定「上一步」「下一步」跳到哪里。用游戏刻看整机变化，用阶段追踪更新顺序，用事件检查具体方块、父事件和活塞进度。切换粒度不会丢掉未展开的方块变化。
- 当前事件的坐标、方块和上级事件按字段列出；方块变化只列出改动的属性（例如 power 15 → 0），点上级事件的编号可跳过去。宽屏时这张信息卡贴着目标放在 3D 视图里，方块事件的引线指向橙色方块框，实体事件的引线指向对应的白色碰撞箱：卡片优先放在目标右侧，放不下就换到左侧、下方或上方，转动视角时跟着目标走。没有坐标的事件把卡片放在「3D VIEW」标签下面；播放时卡片收起，只在「3D VIEW」后面显示一行事件名。窄屏时信息卡在列表下方，宽屏的列表也不再显示坐标。模型上当前事件的方块是橙色实线框，引起它的上级事件的目标同时用灰白虚线框标出，两者是同一个方块时只画橙框。
- 同一游戏刻里的事件按上下级排成一棵树：上级事件的记号下方垂下一条竖线，它的子事件从这条线上分出，最后一个子事件处竖线收尾。按「阶段」显示时，阶段直接挂在维度刻下面。双击一行（或选中后按回车）展开它的下一级，再双击收起；折起的行在名称后标出「+N」，表示还有 N 个下级。行号是事件在这一刻里的序号，展开或收起都不会改变。
- 列表里每条事件刻线的末端带一个类型记号：■ 方块变化、◇ 更新、○ 计划刻、□ 方块事件、▶ 活塞、+ 游戏事件、● 实体；阶段行不带记号。设置卡里有同样的图例。
- 点一下 3D 视图或用 Tab 移进回放后，可以用键盘操作：空格播放 / 暂停，← → 上一步 / 下一步。在速度输入框和打开的设置卡里按键不受影响。把鼠标移到视图上时，「3D VIEW」旁边会提示「拖动旋转 · 滚轮缩放」；在模型上拖动或缩放过一次后不再提示。
- 列表顶部固定显示当前几行所属的游戏刻和事件数。没有在书签里保存镜头时，默认视角会把机器放在画面中央（宽屏时是面板左边空白处的中央）并推近到空白处的七成左右，「复位视角」也回到这个视角。
- 播放速度按游戏刻计时。同一刻内的多个阶段或事件按记录顺序分摊该刻的展示时间；录制只提供这些事件的先后关系。可以慢放或暂停逐步检查。控制条里的链接图标（复制此刻的链接）会保留当前回放位置。
- 带实体的回放和静态投影默认显示实体框。白框表示碰撞箱，红线标出生物的眼高，蓝线沿视线伸出两格。左下角控制条的设置卡里有「实体框」开关，焦点在画面内时也可按 F3+B。倒放、逐步前进或跳转时，实体框都会跟随当前这一步。
- 文章用自己的 WebGL 画布显示结构。博客随站提供从 LitematicWebViewer 提取的渲染代码、原版模型和贴图。静态投影在浏览器内解析。回放直接绘制方块、移动活塞和录制中的玩家。玩家的站位、朝向按游戏实际记录的步骤恢复，支持前进、倒退和跳转。导出器会从本机 Minecraft 的 `assets/skins` 缓存匹配玩家皮肤并随场景保存；录制目录移到别处后，可在导出命令中加上 `--skin-cache "路径/assets/skins"`。缺少皮肤时会显示原版默认外观。录制到的其他原版实体按各自尺寸绘制碰撞箱。旧导出若缺少普通实体轨迹，可从同一份原始录制重新导出。录制没有提供姿态时按该实体的默认姿态显示。

日常写文章和部署站点只需博客仓库。要同步新版渲染代码或原版资源，在博客根目录运行 `node scripts/mc-vendor-renderer.mjs "<查看器源码目录>"`，该目录需已安装依赖并备好原版资源。再运行 `npm run check:mc` 核对模型和回放。静态投影可以使用托管在博客同源地址上的玩家皮肤，外站皮肤使用随站提供的默认外观。
