# 在文章里展示红石结构和运行状态

一段录制可以在多处正文中引用。每张插图都有自己的初始镜头和事件书签。插图接近视口时自动渲染 3D 模型，初始停在文章书签或录制起点。配置了封面时，加载期间先显示封面。

## 在游戏中录制

在运行 MicroTimingReplay 的 Java 版游戏里创建一个独立的录制。用两个角点圈住输入、线路以及需要观察的装置，再触发开关。例如，下面的命令录制 200 个游戏刻。把示例坐标替换为电路的实际范围。

```text
/mtr profile create lamp
/mtr profile area add lamp 100 64 100 106 69 105
/mtr record lamp 200
```

触发电路后等录制结束，也可以执行 `/mtr record stop`。对于现有 profile，MTR 再次开始录制时会追加事件。单独录制一次完整动作最容易和文章对照。

## 导出并试播

录制结束后，按住左 Alt 选「录像管理」，在左栏选中这段录制，点右栏的「导出…」。对话框里填好场景名（默认就是录制名）和导出目录，点「导出」。也可以在聊天栏执行：

```text
/mtr export lamp
```

模组（1.0.5 起）直接写出文章读取的 `scene.json`，不用再跑博客里的转换脚本，写出的内容和下文的脚本逐字节相同。默认写到游戏配置目录下的 `config/mtr/scenes/lamp/scene.json`，目录结构和博客的 `assets/minecraft/` 一样，把 `lamp` 文件夹整个放进博客的 `assets/minecraft/` 即可。单人游戏里，对话框的「打开文件夹」和聊天栏中的路径都能打开所在的文件夹。

也可以让模组直接写进博客。在导出对话框里把导出目录改成博客的 `assets/minecraft`，或者在聊天栏设置一次，以后每次导出都落在 `assets/minecraft/<场景名>/scene.json`：

```text
/mtr exportfolder set D:\项目\Gudu.blog\gudu.blog\assets\minecraft
```

`/mtr exportfolder` 显示当前目录，`/mtr exportfolder reset` 恢复默认目录（对话框里是「默认」按钮）。改导出目录需要 4 级权限，开了作弊的单人游戏里自己就有。场景名只能用小写字母、数字和连字符。命令里场景名默认就是录制名，录制名不符合时在后面写上场景名，例如 `/mtr export Lamp_1 lamp`；对话框会直接换成可用的写法（`Lamp_1` → `lamp-1`），可以再改。录制跨了维度时，对话框里多一个「维度」按钮，命令则在最后加上维度：`/mtr export lamp lamp minecraft:overworld`。同一维度内的多个选区会合并。

已有的 `scene.json` 不会被覆盖，因为里面可能已经加了书签和封面；重新导出前先删掉旧文件，或者换一个场景名。导出用的是当前游戏的方块注册表，所以要在和录制时同一套模组下导出；加了方块的模组也不需要另外提供状态表。

然后启动本地预览：

```powershell
npm run dev
```

浏览器打开 [本地 lamp 预览](http://localhost:4173/preview/minecraft/lamp/)即可看到模型和时间轴。这个地址由本地预览服务器提供，导出后就可以试播，文章可以稍后再写。变更配置后刷新页面即可。

### 用博客脚本导出

进不了游戏时，也可以在博客仓库根目录转换原始录制，结果和模组导出的相同。1.21.10 分支把录制写在 `config/mtr/<存档标识>/<录制名>/`，导出器读取其中的 `record.dat` 和 `profile.dat`。前者是起始世界快照，后者包含按游戏刻组织的事件。原始录制可以放在仓库外。

```powershell
npm run mc:export -- "D:\录制\lamp" "assets/minecraft/lamp/scene.json" --minecraft 1.21.10
```

脚本同样不覆盖已有的输出。它按本项目使用的 MicroTimingReplay **Java 版 1.21.10** 录制格式编写，内置这个版本的原版方块状态表。改变方块注册表的模组需要加上 `--registry "路径/reports/blocks.json"`，提供与录制环境一致的状态表。其他游戏版本还需要录制格式兼容。对于跨维度录制，可以加上 `--dimension minecraft:overworld` 选择一个维度。

## 设置文章书签

在本地预览里逐步前进到想讲解的事件，旋转模型选好角度，点击「复制书签配置」。在 `scene.json` 末尾的 `bookmarks` 对象中新增一个名称，将复制的对象作为它的值。第 0 步代表录制起点，第 1 步代表第一个事件执行后。界面显示世界坐标，配置中的 `focus` 使用相对于 `origin` 的方块坐标。

```json
"bookmarks": {
  "lamp-update": {
    "step": 2,
    "focus": [1, 0, 0]
  }
}
```

上面的步数和方块位置仅用来说明格式，以实际录制为准。复制出的 `camera` 可一起保留。要用封面，将图片放在 `scene.json` 旁，在书签中加入 `"poster": "lamp-update.webp"`。场景顶层的 `poster` 可作为所有书签的默认封面。保存后，打开 [带书签的本地预览](http://localhost:4173/preview/minecraft/lamp/?bookmark=lamp-update) 可检查落点。

## 在 Markdown 中引用

文章放在 `content/posts/`，分类填写 `Minecraft`。正文中使用以下围栏。省略 `bookmark` 时从录制起点打开。

````markdown
```mc-scene
scene: lamp
bookmark: lamp-update
granularity: event
speed: 2
speed-unit: event/s
loop: true
autoplay: true
caption: 红石灯收到邻居更新。再前进一步，观察灯的 lit 属性。
```
````

运行 `npm run build` 生成文章页。正式文章会检查场景、书签和本地资源是否存在。标记为 `draft: true` 的文章可以提前写好围栏，等录制完成再发布。

`granularity` 设置每个回放打开时的显示粒度，也决定手动单步前进的步长。可以写 `tick`（游戏刻）、`phase`（阶段）或 `event`（事件），也可以直接写对应的中文名。省略时使用 `phase`。读者可以在播放器的设置里临时切换。

如果录制时给选区绑定了跟随方块，且录像里有选区移动记录（`areaMove`），播放器会自动跟随。比如飞行器的黏液块向东移动一格，镜头和旋转中心会一起平滑移过这一格，保留读者调整的角度和缩放。过渡随播放速度调整，在 10 gt/s 下约为 150 毫秒。暂停、单步、拖动进度或循环回到起点时，镜头直接对齐对应步骤。系统开启「减少动态效果」时，播放中也直接对齐。

多个选区都有移动记录时，默认跟随最先移动的选区。读者可以在播放设置的「相机跟随」里选择其他选区，或选「固定视角」观察装置在世界里的位移。

`autoplay: true` 让回放在首次进入视口、模型就绪后自动播放。省略或写 `false` 时由读者点击播放。手动暂停或移出视口后，再次播放需要点播放键。通过「复制此刻的链接」打开时，会停在分享的那一步。

`loop: true` 开启循环播放。回放播到结尾会从录制起点继续，并保留当前镜头。按事件或阶段计速时，最后一步会显示一个完整的间隔。写 `loop: false` 或省略此项时，播到结尾自动停止。两个选项可以单独使用。

用 `speed` 设置这张回放的默认速度，用 `speed-unit` 指定单位。速度可以是大于零的小数。上例是每秒推进两个事件。

| `speed-unit` | `speed` 示例 | 播放效果 |
| --- | --- | --- |
| `gt/s`（默认） | `5` | 每秒 5 个游戏刻 |
| `s/gt` | `2` | 每 2 秒推进 1 个游戏刻 |
| `x` | `0.5` | 半速，每秒 10 个游戏刻 |
| `event/s` | `2` | 每秒 2 个录制事件 |
| `phase/s` | `3` | 每秒 3 个阶段步，与「阶段」单步使用相同的停靠点 |

省略这两个字段时沿用场景的 `playbackSpeed`（GT/s），场景也未设置时使用 **20 GT/s**。单独设置 `speed-unit: event/s` 或 `phase/s` 时，每秒推进一步。按事件或阶段计时会跳过空刻。列表粒度和手动单步仍由 `granularity` 决定。读者可以在播放设置里改速度或单位，点「设为默认」会保存个人偏好，优先于文章设置。点「恢复默认」可重新使用文章设置。

只展示静态投影时，在场景目录放入投影文件，并将 `scene.json` 写成 `{"version":1,"schematic":"door.litematic"}`，正文沿用同一语法。

静态投影和运行回放默认启用 XeKr 的 **XK Redstone Display 26.3.0**。红石粉上的数字随信号强度变化，未覆盖的资源沿用原版。文章直接引用原有场景即可。[作者发布页](https://modrinth.com/resourcepack/xk-redstone-display)。

## 回放中可以核对什么

- 宽屏时事件树立在 3D 视图右侧、没有底框，游戏刻的编号在每一行最右端，事件直接从树干分叉；刻度尺竖在树的左边（上端第一刻、下端最后一刻）；游戏刻读数、播放按钮、设置和两个链接收在视图左下角的控制条里。窄屏时它们排在模型下方，刻度尺横向。整个回放区域是一层半透明黑底（日间为白色），文章背景的星空变暗后仍隐约可见。滑条以游戏刻为单位。拖到没有事件的刻时，时刻显示继续前进，模型保持最近一次变化后的状态。新版导出器保留录制开头和结尾的空刻；旧场景缺少范围时，以已记录的事件确定起止刻。
- 播放速度和显示粒度收在控制条的一行摘要里，点设置图标会浮出一张设置卡，点卡外或按 Esc 关闭。列表可连续滚动；滚离当前行时，列表边缘会出现「当前 · 第 N 刻」，点一下回到当前行。显示粒度有「游戏刻」「阶段」「事件」三档，未在文章中设置时使用「阶段」；它也决定「上一步」「下一步」跳到哪里。用游戏刻看整机变化，用阶段追踪更新顺序，用事件检查具体方块、父事件和活塞进度。切换粒度不会丢掉未展开的方块变化。
- 当前事件的坐标、方块和上级事件按字段列出；方块变化只列出改动的属性（例如 power 15 → 0），点上级事件的编号可跳过去。宽屏时这张信息卡贴着目标放在 3D 视图里，方块事件的引线指向目标方块的框，实体事件的引线指向对应的白色碰撞箱：卡片优先放在目标右侧，放不下就换到左侧、下方或上方，转动视角时跟着目标走。没有坐标的事件把卡片放在「3D VIEW」标签下面；播放时卡片收起，只在「3D VIEW」后面显示一行事件名。窄屏时信息卡在列表下方，宽屏的列表也不再显示坐标。模型上的标记按事件类型分颜色和形状：当前方块按工程图描框，排队中的事件（加入计划刻、加入方块事件）用虚线框，活塞运动有方向箭头，游戏事件是扩散的圆环。引起它的来源（上级链上第一个不在同一格的事件）淡淡描出，相邻时用箭头或相接的面连过来，不相邻时用虚线箭头。各类型的颜色见设置卡里的记号图例。游戏里看不见的方块也会显示：屏障、光源和结构空位在方块中心显示游戏里的物品图标（光源按亮度显示对应等级的图标）；移动中的活塞（b36）那一格画活塞蓝的角标，某一步缺活塞数据时画成整格细框，信息卡会注明。静态投影也一样显示这些方块。
- 同一游戏刻里的事件按上下级排成一棵树：上级事件的记号下方垂下一条竖线，它的子事件从这条线上分出，最后一个子事件处竖线收尾。按「阶段」显示时，阶段直接挂在维度刻下面。双击一行（或选中后按回车）展开它的下一级，再双击收起；折起的行在名称后标出「+N」，表示还有 N 个下级。行号是事件在这一刻里的序号，展开或收起都不会改变。
- 列表里每条事件刻线的末端带一个类型记号：■ 方块变化、◇ 更新、○ 计划刻、□ 方块事件、▶ 活塞、+ 游戏事件、● 实体；阶段行不带记号。设置卡里有同样的图例。
- 点一下 3D 视图或用 Tab 移进回放后，可以用键盘操作：空格播放 / 暂停，← → 上一步 / 下一步。在速度输入框和打开的设置卡里按键不受影响。把鼠标移到视图上时，「3D VIEW」旁边会提示「拖动旋转 · 滚轮缩放」；在模型上拖动或缩放过一次后不再提示。
- 列表顶部固定显示当前几行所属的游戏刻和事件数。没有在书签里保存镜头时，默认视角正对机器较长的那一面，让这一面露出的面积最大、短边朝画面里伸：从这一面的正前方往读者左手边偏 25°、仰角约 26° 看，所以长面的右半边往画面里退。两个长面里选能看到录制里玩家的那一面，没有玩家时从南面（南北向更长的结构从东面）看；静态投影也这样摆。默认视角还会把机器放在画面中央（宽屏时是面板左边空白处的中央）并推近到空白处的七成左右，「复位视角」也回到这个视角。
- 使用游戏刻单位或倍速时，播放按游戏刻计时。同一刻内的多个阶段或事件按记录顺序分摊该刻的展示时间；录制只提供这些事件的先后关系。可以慢放或暂停逐步检查。控制条里的链接图标（复制此刻的链接）会保留当前回放位置。
- 带实体的回放和静态投影默认显示实体框。白框表示碰撞箱，红线标出生物的眼高，蓝线沿视线伸出两格。左下角控制条的设置卡里有「实体框」开关，焦点在画面内时也可按 F3+B。倒放、逐步前进或跳转时，实体框都会跟随当前这一步。
- 文章用自己的 WebGL 画布绘制模型。静态投影和 MTR 回放共用方块、物品、载具和生物模型。关闭「实体框」后模型仍然可见。矿车会沿轨道摆放，TNT 实体在录制的生成步骤出现，回退一步即可看到它消失。保存在录制中的物品、装备、方块状态和展示变换会随场景导出。旧场景如果缺少这些字段，可以从原始录制重新导出。
- 标记实体（`marker`）和交互实体（`interaction`）在原版里没有可见模型。展示实体按保存的方块、物品或文字绘制。闪电和区域效果云使用静态效果示意，MTR 记录的事件中没有客户端的随机粒子轨迹。
- 导出玩家皮肤时（模组和脚本相同）优先使用录制中的纹理标识和本机 `assets/skins` 缓存。缓存缺失时可从 Mojang 下载对应的 PNG。如果录制只提供正版账号标识，导出器可查询该账号当前的公开皮肤。成功取得的图片随场景保存，读者打开文章时直接从博客加载。离线或查询失败时使用默认皮肤。场景里只有皮肤图片，不写账号标识、玩家名和签名。用脚本转换另一台机器上的录制时，可用 `--skin-cache "路径/assets/skins"` 指定缓存目录。

日常写文章和部署站点只需博客仓库。要同步新版渲染代码或原版资源，在博客根目录运行 `node scripts/mc-vendor-renderer.mjs "<查看器源码目录>"`，该目录需已安装依赖并备好原版资源。运行 `npm run check:mc` 检查回放与导出。要逐个验证 Java 1.21.10 实体模型和画作贴图，在本地预览服务运行时执行 `node scripts/check-mc-entity-models.mjs`。这个检查会启动无头 Chrome，遍历原版注册的 153 种实体。静态投影可以使用托管在博客同源地址上的玩家皮肤，外站皮肤使用随站提供的默认外观。
