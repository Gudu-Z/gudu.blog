# Gudu 的个人博客

使用原生前端的静态个人博客，沿用极简科技风与深色太空首屏：两行标题、实时日期时间，以及暖白与淡琥珀色的实时 WebGL 黑洞。成组细线随盘面流动，鼠标控制相机视角，背景是一层带纵深的清晰星点。首屏之后依次是自我介绍、分类、最新文章和归档，支持移动端导航、RSS 订阅和完整的文章阅读页。Markdown 和 YAML 只在构建时解析，浏览器不加载这些依赖。

目前等待作者提供真实文章，因此文章和归档展示待更新状态，没有填充示例文章、虚构统计或不可用的社交链接。搜索入口保持可用，尚无文章时显示真实空状态；加入文章后，分类、文章计数与分页会自动启用。最新文章的空状态不再画轨道图标（章节背后的黑洞本身就是那条轨道），文字在面板里居中；归档的空状态把时间线延续到面板底部：虚线表示还没写下的时间，每一级有一个刻度和一条空位，逐渐淡出。

宽屏桌面的标题与黑洞共享居中的构图区域，最大宽度为首屏实际高度的 16/9；黑洞尺寸也按该高度封顶。超宽屏两侧延伸星空背景，避免黑洞随屏幕宽度持续放大。手机端保留独立的竖屏布局。

## 线上访问

[打开 Gudu 的个人博客](https://gudu.blog/)

GitHub Pages 从 `main` 分支的根目录发布，推送更新后自动部署。`.nojekyll` 让页面和静态资源直接发布。

## 本地预览

需要 Node.js 22.12 或更新版本。首次使用或依赖锁定文件更新后，先执行 `npm ci`：

```sh
npm ci
npm run dev
```

打开 http://localhost:4173 。也可以直接打开 `index.html`，所有视觉资源均在本地，不依赖 CDN。

预览服务器支持 RSS、站点地图和自定义 404。内容修改后先运行 `npm run build`；仅修改 HTML/CSS/JS 时刷新页面即可。

## 首页章节

在首页“分类”点选一列即可展开文章目录。桌面停在分类章，旁边的章节沿弧线退下：先竖直下沉，再朝各自的外侧弯开，关闭时沿原路回来。镜头随分类面板向上转，背后的黑洞和星空一起向下转出画面底部（见“黑洞视觉”）。标题末尾的橙色句点先退格，再打出“文章目录”。面板随之放平，文字保持清晰。所选列向右加宽，宽度正好放下这一类的整排卡片：原处的标本停在悬停时的展开姿态，移到取景框正中并调暗；子分类标题和磨砂玻璃的文章卡片排成一行，各组按最高的一组对齐；没有文章的分类显示一张虚线边的空位卡（“00”和 NO ENTRIES）。右侧各列随之右移，可以移出屏幕。加宽后面板若越出右框，整块面板向左滑，直到所选列左沿对齐第一列原来的左沿，或面板右端回到展开前的位置。

桌面底部的四个站名随目录换成分类名，点另一列或另一个站名即可换分类。滚轮、触摸拖动、左右方向键和 Page Up / Page Down 移动整块面板，Home / End 跳到当前分类的开头或末尾，Tab 会把聚焦的卡片带入视野。读到一个分类的末尾继续往后滚：下一个分类完整进入画框后再往前 40px，就在原处展开，画面不跳；往回读时同理。阅读线（顶栏 Logo 左沿到工具组右沿的正中）离开的那个分类，只要收起后面板两端仍不露空，就朝阅读线的方向收起，约 0.45 秒。游标随阅读位置在各分类之间连续移动，也可拖动横轴直接定位。手机上所选分类占满一行，文章按组纵向排列，随页面滚动依次显现，右侧刻度带始终显示首页章节名。

点顶栏下方的“返回分类”或按 Esc 可收起目录。点顶栏 Logo 回到首屏，提交搜索进入最新文章。打开或切换分类会记入浏览器历史，直接访问或刷新 `#catalog-daydreams` 会落在展开的“白日梦话”。地址加上 `?catalogslow=1` 可以五分之一速度查看转场。开启“减少动态效果”时，标题和卡片立即就位，面板保持平直。

向下滚动或滑动即可从主视觉整段切入自我介绍，回到主视觉时也采用整段切换；键盘方向键、Page Down、空格和“跳到主要内容”链接也能进入。主视觉底部不显示介绍文字；入场落定后，框线内的底部正中只有一个小小的 SCROLL 提示，细线里一段亮光缓缓下落，点按也会进入关于。第一次离开首屏后它就不再出现，回到首屏也不会再出现。黑洞在约 900 毫秒内缩至原构图的 34%、移到画面正中心并消除画面滚转，俯仰保持与主视觉一致（极简 81°、水墨 83°），首屏文字退场。远景盘面沿用主视觉的材质亮度与辉光，不另加柔光，也不提高背景底色或星空亮度。极简主题缩小后只保留每三条细线中的一条，并在盘面上加宽为三倍，使屏幕上的线宽与间距和主视觉一致，不会挤成一片发白的光带；两种线距在镜头移动中段经平均覆盖率衔接，仍只做一次线条过滤。半透明黑色直角面板（88% 不透明，黑洞只隐约透出）通过阴影分层，不描外框，只保留极淡的 1px 细边、顶部细高光和左上、右下两个定位角标；角标画在背景层上，不占用面板到位时的点亮装饰。分类、最新文章和归档的标题使用同一字重与字距，末尾统一为首屏“个人博客”后的橙色方块。面板之间保持固定间距，当前章节右侧能露出下一章的一部分。顶部工具栏和黑白灰仪表盘在进入内容区后出现。顶部透明悬浮，左侧保留 Logo 与双行站点文字，右侧提供搜索框与 RSS，中央留空；按回车或点击搜索会切到最新文章显示结果，并保留顶部输入焦点，文章面板不再重复放置搜索框。底部承担章节导航与位置提示，以水平基线和竖向分隔刻度串起关于、分类、最新文章、归档四个区域，当前区域白色点亮。

首屏切入使用一条约 900 毫秒的时间线：标题与时钟错开退场，完整面板从右侧接入，关于区的编号与头像先显现，姓名、档案字段和个人链接随后错开展开，自我介绍与底部识别条最后落位，表格细线随所在的字段一起出现，右侧入口卡片逐层接入；内容层在同一切换进度的 96% 前完成，返回 Hero 时按同一坐标反向收起，不新增计时器或动画帧循环。顶部 Logo、站名和副标先依次显现，校准细线展开、橙色短线轻亮，搜索和 RSS 再错开就位，RSS 两道弧线分别描出；顶部在约 720 毫秒时完成，切换全程保持不可聚焦，搜索框沿用原有展开交互。顶部与内容共用可反向的切换进度，底部基线与刻度同步逐层出现。黑洞在中段短暂增加局部辉光，峰值为已有辉光的 1.3 倍，随后恢复；背景和星空不参与这一脉冲，也不增加渲染通道。返回主视觉约 680 毫秒，界面收起后标题恢复。直接访问章节链接不播放启动动画，章节之间继续平滑横移；面板保持固定透明度，文字保留独立的错层入场和退场动画，停稳后短暂点亮细线与编号。面板与其外部标题共用画面中心的透视视点，按近→远→近的轨迹运动：每张平面连接同一弧面上的左右端点，旋转、纵深和尺寸由这两个端点统一确定，靠近边缘时充分侧转并放大，大面板也不会被单独压低倾角。各端点保持在阅读平面前方，并维持相邻边缘的顺序；弧面仅在整张面板出画后截断并继续向外延伸。仅实际内容过长的区域启用原生纵向滚动，并按未变换的正文高度限制阅读范围，避免透视投影制造额外空白；滚动容器额外保留横向投影空间；窄屏文章主卡与下方半宽卡之间留出 32px 纵向间距，避免不同深度的面板相碰。窗口缩放、隐藏页面或开启减少动态效果时会完成当前导航并清除装饰状态，离开页面时停止动画。

滚动更新只使用一条动画链：已同步绘制的位置不再由随后到达的 scroll 事件重复更新。面板直接更新自身 transform，进度变量限制在底部导航内；未变化的样式、class 和 inert 不重复写入。游标通过 transform 移动，窗口重测先集中读取几何再写入布局。每次更新先读取页面与各章节的滚动位置，再写入切换相位、进度等根变量：这些变量会让整页重算样式，先写后读会在同一帧内强制多次重算。首屏切换的起点、终点与空闲检查复用同一任务中已读到的位置。切换期间，关于区逐行入场的内容、面板方向光的两层渐变和背景网格各自获得独立合成层，逐帧变化的透明度与位移由合成器混合，不再让整块面板（连同头像）每帧重绘、重新光栅化；网格淡出因此改用 opacity，而不是 filter: opacity()。切换结束后这些合成层随即释放。黑洞光线积分复用上一步终点的加速度，保持原有步长、光路与分辨率；静止视差图层和平面星空也不再随黑洞每帧重绘。自动检查记录这些路径的工作量，并比较光线结果的一致性；它们不替代真实设备的帧率测量。

顶部搜索平时只显示图标，鼠标悬停或键盘聚焦时向左展开；触屏可点击图标打开。展开后用同一个放大镜或回车提交搜索，不再显示重复的文字按钮。输入期间保持展开，鼠标与焦点均离开后收起，Esc 可关闭并返回图标焦点。

底部使用精密刻度样式，以长分隔与暗色短刻度区分层级；宽屏按比例细分刻度，细刻度约 20px、中刻度约 80px 一根，与 1440px 屏幕相近，并始终对齐站点。游标（白色三角、橙色竖线）连续跟随横移，到达每章时停在该格中央。当前章节从本站竖线到下一站之间的整段横轴白色亮起。切换章节时，光从游标穿过的那根竖线进入新的一格，旧的一格同时收回到这根竖线，向左移动时方向相反；进出首屏时随横轴一起从左向右展开。悬停或聚焦其他站名时，该段直接淡入。刻度尺像一块放大镜下的仪表（`js/ruler-lens.js`）：刻度是一根根单独的元素，各自待在所属的那一格里，跟着折面一起折。游标周围常驻一个小鼓包，附近的刻度变长、变亮，刻度之间显出更细的分度（每个间隔三根），游标移动或被拖动时鼓包更明显。鼠标经过横轴时，鼠标附近鼓起一个更大的鼓包，点击落点处有一条细竖线，上方的读数写着落到哪一站、站名和位置，例如「03 最新文章 67%」（和游标的读屏数值同一种算法：第一站中心为 0%，最后一站中心为 100%），对应站名也稍微变亮；拖动游标或用键盘移动游标时，这条细竖线和读数跟着游标走。鼠标移到站名上（或键盘聚焦）时，这一格的刻度从左到右起一道波，减少动态效果时不起波。落点细竖线像被磁铁吸向附近的章节中心：鼠标离中心不到一格宽度的 1/40 时，细竖线停在中心；从 1/40 到 1/8，它沿一条三次曲线平滑地回到鼠标自己的位置（靠近时被拉过去、离开时先被拖住再追上），位置和速度都不跳变，读数也连续变化。点击就落在细竖线显示的位置。拖动游标后松手，离某章中心不到一格宽度的十分之一时，平滑滑到该章中央，其余位置保持原样；拖动过程中不吸附。滑动时游标带轻微光晕。静止约 1 秒后，游标光晕以 4 秒周期轻缓呼吸，当前区域的三个短刻度每 9 秒依次亮起一次，扫光过程约 0.8 秒。导航只用黑白灰，暖橙色 `#f06446` 只用在游标竖线上。滚动、导航和触摸期间停止循环，停下后重新等待；循环由 CSS 驱动，不增加持续的 JavaScript 定时器或动画帧。用鼠标或触屏操作完标尺后，焦点交还页面（之前已用 Tab 选中游标时仍留在游标上），Page Down、空格和方向键保持原来的移动方向；用 Tab 选中游标时按滑块操作：方向键移动 1/20 章，Page Up / Page Down 移动一章，Home / End 到首尾，空格不滚动页面。手机上标尺竖在右侧，见下文的手机竖向首页。页面离开或隐藏时清理反馈，系统减少动态效果时保留位置指示与静态橙色点缀并关闭装饰动画。

窗口越高，章节面板上下的留白越大（窗口高度的 14% 和 17%），顶栏和刻度条也跟着往里收：宽屏上各收进面板留白比 860px 高的窗口多出部分的一半，顶栏另外离上沿多留 6px；面板的可见范围随之收窄，不会盖到仪表上。1600×860 下顶栏下移 6px、刻度条不动，1774×1266 下两者各收约 35px。

关于区是一张个人档案卡：头像和下面两行个人主页链接保持原来的样子，右栏从上到下是姓名、档案表（现居、身份、爱好、最喜欢的类型和玩的游戏）和自我介绍；横跨卡片底部的是一条机读码样式的识别条（姓名与站点标语，只作装饰，屏幕阅读器会跳过）。每个字段都是中文名加一行小号英文代号，字段之间用细线分格。头像随章节高度缩放，比原来略小，窗口不超过 820px 高时再小一些，好让右栏放下自我介绍；窗口比卡片高时，卡片在面板中上下居中，识别条贴在面板底部。手机上从上到下依次是头像、个人主页、姓名、档案表、自我介绍和识别条。

桌面宽度（1201px 以上）的章节内容按 640px 高的章节绘制，窗口更矮时排版和间距随之等比缩小（最小到 0.72 倍），14px 及以下的正文保持原字号；关于与最新文章在窗口高度不超过 820px 时再收紧行距与间隔，头像最小 220px。关于的两列此前至少 510px 高，窗口低于约 740px 时会把面板顶出刻度条，现在只填满章节本身的高度。面板在弧面透视下两端比自身各高出约 18px；窗口矮到面板留白与裁切边之间放不下这段余量时，留白自动加大，避免面板两端被顶栏和刻度条下的裁切边切掉。实测 1280×720、1366×768、1440×810–840、1536×700–860、1680×900 和 1920×960 下四个章节都完整显示在刻度条上方；窗口高度低于约 700px 时，放不下的章节仍可在章节内竖向滚动。

宽屏上，底部刻度条和顶栏的两端向内折，像座舱里的仪表围着读者：刻度条的首尾两格连同站名，以与中间相邻的那根站线为折痕，朝读者折过来 8°，中间两格保持平直；顶栏的 Logo 区以内侧边、右侧工具组以搜索图标的左沿为折痕，各折过来 6°，搜索框展开时向左长出，图标不动。折面和章节面板共用一个相机，透视中心都在屏幕正中，所以刻度条两端略微下沉，顶栏两端略微上扬；两者再各自往屏幕中间挪回这段偏移的一半（1600×860 下刻度条上移约 5px，顶栏下移约 2px），平均下来仍停在原来的高度。透视同样会把两端往外推，所以刻度条按折后的落点收窄排布，Logo 区和工具组也各自挪回：折完后，刻度条两端、Logo 左沿和工具组右沿仍落在平铺时的外框上。游标、刻度提亮、悬停细竖线和空闲扫光走到首尾两格时随折面一起转动；悬停、点击和拖动都把鼠标在折面上的位置换算回平直的刻度，落点细竖线始终在鼠标正下方，对焦框的卡尺也随折面下沉，拖动时游标不离开鼠标。折过来的站名、英文标签和格内空白仍是站点链接，这一格横轴上下各 19.5px 仍归横轴，和平直的格子一样。屏幕较高或较窄时（如竖放的平板），折角自动减小，让两端不出屏：顶栏外角距屏幕上沿至少 4px，站名距屏幕下沿至少 4px。减少动态效果时两者保持平直。

手机竖向首页：宽度不超过 720px，或横屏高度不超过 520px 的触屏上，首页改成一整页竖向滚动，平板与桌面仍是横向。首屏、关于、分类、最新文章、归档从上到下排列，各章按内容自然展开，没有章节内的嵌套滚动。首屏到关于仍是两段：从首屏第一次上滑、转动滚轮或按键，约 900 毫秒落到关于，黑洞同时缩到背景中央、首屏文字退场；在关于的起点往回滑，约 680 毫秒回到首屏；滚动停在两者之间时，顺着原方向补完。其余都是原生滚动。横向的弧面竖过来使用，每个区域仍是一整块直的平板，和桌面端一样：面板连同属于它的标题共用一个平面，按面板在屏幕内那一段的上下两端取弧，屏幕中段放平，从底部升起时整块前倾、离开顶部时向另一侧倾。比屏幕还高的面板铺满屏幕时是平的，只在边缘进出时倾斜。离开屏幕的面板停在即将进入的边缘姿态，超过一屏后不再更新，所以快速滑动时图层不会反复创建。前凸幅度为横向的四分之三，放大时以阅读栏的中线为中心，面板向外扩时不会伸进刻度带。文字和图片按块入场：每段文字进入视野时从下方 28px 上升淡入，“关于”的头像从上往下逐行扫描显现，同时进入的几块按阅读顺序错开约 70 毫秒；一块完全离开屏幕后悄悄复位，再滑回来时重新播放。顶栏下方和屏幕底边各有一层渐隐。

手机上的标尺竖在右边缘，像飞机的高度表：轴线自上而下，带 01–04 编号的竖排站名挂在轴线内侧，刻度朝向屏幕边缘，每条站线横穿轴线并压在编号上方；当前章节的编号、站名与轴段亮起，游标是从屏幕边缘指向轴线的白色三角和横穿轴线的橙色短线。游标同样带着放大镜：刻度带从它下面滑过时，经过游标的刻度朝屏幕边缘伸长、变亮，中间显出更细的分度。刻度带按站点分成四格，和面板贴在同一条弧上，越靠两端越倾斜、越紧凑，像滚筒上的刻度；它向外凸出的幅度是面板的六成，两端和旁边的面板一起向外弯，不会叠到面板上，也不会出屏。游标固定在刻度带窗口的正中，这条线就是阅读线；刻度带在它下面滑动，每章一格，格高是窗口的七分之一，所以从页顶到页底刻度带两端始终都在视野里。内容里的章节交界越过阅读线时，站点竖线也正好越过游标。屏幕太矮、格子放不下站名时（如手机横屏），整条刻度带铺满窗口不动，改由游标移动，拖动时像滚动条。进入关于时游标正好指着关于，滑到页底正好指着归档。在刻度带上任意位置拖动，刻度带跟着手指走，每帧只滚动一次页面，手指在刻度带上时页面本身不跟着平移；点轴线上的一点，那一点滑到游标处；点站名，跳到该章开头并新增一条历史记录。松手或点按的位置离章节中心不到一格的十分之一时，停到中心。阅读时网址锚点随当前章节更新，刷新或直接打开章节链接（包括 404 页导航里的“关于”）时从该章开头显示：浏览器自己处理锚点时也落在同一位置，加载完成后的最后一次校正只会被读者自己的触摸、点按、滚轮或按键取消。最新文章的分类筛选行放不下时单独横向滑动，不带动页面；滚动条隐藏，可继续滑动的一侧渐隐进面板；用 Tab 或点按选中的分类会滑进视野。阅读栏右侧为刻度带留出 50px。用 Tab 选中游标后按滑块操作，向下为前进。窗口跨过断点时两种布局互相交接：网址记下正在读的章节，另一种布局从这一章打开。减少动态效果时不弯曲，跳转直接到位。

进入与离开首屏采用分段切换；内容章节之间，滚轮的距离连续映射为面板从右向左的移动，不逐章吸附。背景与上下导航保持固定，点击导航可平滑抵达指定章节。桌面的长内容在章节内竖向滚动，到边界后继续横移。手机沿页面上下阅读。章节链接保留搜索参数，支持直接访问 `#about`、`#series`、`#journal`、`#archive` 及浏览器返回。系统减少动态效果时跳过缓动并保留连续位置控制；WebGL 不可用时回退图也会缩小、提亮、转平和居中。关闭 JavaScript 后保留正常文档流和锚点导航。

分类、最新文章和归档的内部细节随横向滚动产生轻微视差：轨道与路径装饰最多偏移 12px，标签、编号、年份和日期使用更小幅度，正文与链接整体保留原有位置；手机上限为 5px。每个章节到达导航对应的阅读位置时，内部偏移归零。视差叠加在原有文字显隐与面板透视之内，不改变外部标题的所属平面；文章列表更新后自动继承，不需要重新注册动画。它复用现有滚动帧与缓存，不新增持续动画循环，纵向阅读不会带动横向视差；减少动态效果、页面隐藏和离开时归零。

鼠标在内容区内移动时，整个界面分为前景仪表与后方内容两个视觉深度：顶部工具栏和底部刻度条同步跟随，最大横向 8px、纵向 5px；所有面板连同文字、图片和外部标题一起平移，最大横向 6px、纵向 3.75px，以较小幅度表现位于仪表后方。层内间距与原有透视不变，鼠标经过空白、顶部和底部时也连续响应，离开窗口后缓缓归位；原来的装饰独立鼠标偏移已取消。三个界面容器复用现有更新帧，停稳后停止请求动画帧。按下按钮、编辑搜索框或拖动游标时固定当前偏移，刻度条的点击坐标计入实际位移，拖动期间保持游标与鼠标对齐；滚动和页面退出会清理效果，触屏、窄屏与减少动态效果模式关闭此视差。

首页的鼠标指针换成对焦框：四个角标围着一个白点，略微拖后跟随。移到链接、按钮或卡片上时，角标展开并锁定到目标外 5px，角标长度随目标大小在 6–12px 之间变化，白点变成橙色；底部站名框住它所在的整段标尺。按下时对焦框收紧 3px、白点放大。顶部搜索作为一个整体：放大镜、输入框和清除按钮共用一个对焦框，并随搜索框展开和收起；在输入框里换成系统文字光标，对焦框仍围着搜索框，页面滚动时这个锁定保持不变。经过刻度条横轴时，对焦框收成 10px 宽的卡尺，夹住横轴自己的落点细竖线（包括被章节中心吸过去的位置）；悬停或拖动刻度条游标时，对焦框围住它的三角和竖线。变成卡尺或围住游标时，对焦框不是瞬间跳过去，而是在约 0.12 秒内滑过去，拖后逐渐收紧到零；之后紧贴细竖线和游标，拖动时不拖后。按住鼠标期间保持按下时的状态：点击横轴不会跳到远处的游标，真正拖动后才切换为围住游标；点击后的缓动期间卡尺停在落点上。顶部和底部仪表不随页面滚动，滚动时保持锁定，只有不在拖动中的游标被滚走时才松开。这三处由文字光标、细竖线和游标本身指示位置，白点隐藏。第一次移动鼠标前保留系统光标，触屏、触控笔和粗指针设备不启用；减少动态效果时不拖后、不过渡。锁定后的对焦框只在鼠标移动后的 0.4 秒内随视差重读目标位置，目标或其外层的过渡结束时再读一次；页面滚动时，内容区里的锁定先松开，停稳 120 毫秒后再判断鼠标下的元素，不在滚动的每一帧强制布局。文章页保留系统光标。

内容还共用轻微的观察角度变化：鼠标控制水平 ±1.5°、垂直 ±0.8° 的视角，旋转插在统一透视投影内，面板与框外文字继续处于各自所属的同一平面；上下仪表保持前景平移。原有弧面轨迹与布局间距保留，面板不增加厚度或外框。左上方固定光源根据面板与视角合成后的法线决定柔和反射与背光暗部，仅作用于边缘的静态渐变层，不改变正文或背景亮度。角度和光照与平移共用缓动、冻结和退出清理，使用已有面板几何缓存，不增加布局读取或持续动画循环。

## 日间模式

页头右侧的黑洞图标（倾斜的吸积盘与两道喷流）切换日间与夜间模式，日间时两道喷流亮起。首次访问默认夜间；访客的选择保存在浏览器本地，刷新后保留，并同步到已打开的其他标签页。`js/site-theme.js` 在 `<head>` 中同步执行，样式表加载前就设好 `data-theme`，不会先闪一下另一种配色。链接加上 `?theme=light` 或 `?theme=dark` 可预览任一模式，不会改写已保存的选择。首页主视觉没有页头，点黑洞中央的黑色球体切换：球体是一个看不见的圆形按钮，鼠标移上去时对焦框会框住它，键盘也能选中；进入章节后黑洞移到背景里，改用页头的按钮。切换时整页颜色一次到位，不逐个过渡。

样式里的每个颜色都写成 `light-dark(日间值, 夜间值)`，由根元素的 `color-scheme` 选择；遮罩、`@supports` 条件和 `@property` 初始值除外。日间值由 `scripts/day-palette.mjs` 从夜间值推导：在 OKLab 中以夜空 `#080b10` 与日间纸色 `#eef0f2` 为两端镜像明度，保留色相与色度，因此夜间各层级之间的对比关系在日间保持不变；镜像后接近纸色的浅色表面会减弱色调，避免发蓝。橙色 `#f06446` 与 Logo 的琥珀色保持不变，链接等橙色文字改用更深的 `#c0401f` 以保证对比度；黑色阴影保持黑色，透明度降到原来的 45%。新增颜色时运行 `node scripts/day-palette.mjs "#颜色"` 得到对应写法，`npm run check` 会检查每个颜色都有日间值。`light-dark()` 需要 Chrome 123、Safari 17.5、Firefox 120 或更新版本。

日间的黑洞是夜间画面的反色：吸积盘的发光细线变成深色线条，星空变成纸上的深色星点，每颗星的位置、大小和覆盖范围不变，只反转颜色；夜间纯黑的阴影在日间是纯白。反色后的盘面不再发光，渲染器跳过泛光这一道绘制。场景下方的平面星空在日间同样改用反色。水墨主题只在夜间出现，日间始终使用极简黑洞。日间回退图 `assets/black-hole-minimal-day-fallback.png` 与夜间回退图同样由实时画面按同一构图导出。底部章节标尺在日间以深色标出当前章节、其余为浅灰，游标竖线仍为橙色。

切换时，两道纯白的光柱沿黑洞的自转轴，也就是垂直于吸积盘的方向（首屏倾斜 18°，章节中竖直），从黑洞中心向上下两侧射出：先是一根细针，约 0.24 秒射出屏幕并变粗，同时夜间画面以黑洞为中心朝镜头方向顶一下（放大 1.8% 后回弹）。随后光柱加速变粗，直到整屏变成纯白，日间页面再从白光里浮现出来。光柱是实心的白色，里面看不到吸积盘；它经由黑洞场景自己的相机投影：两端的圆在透视下是椭圆，光柱的轮廓取两端椭圆的凸包，变粗时柱壁朝镜头加速逼近。切回夜间时倒放：日间页面先褪成纯白，再收成光柱缩回黑洞。整段约 1.1 秒，由 `js/theme-jets.js` 控制。中途随时再点，光柱都会沿原路退回；若页面已经重新着色，就在原配色的画面盖满屏幕时换回去，并等黑洞以该配色画出一帧，再交还实时页面。从点击起整段都在同一次 View Transition 里：整页只在点击时重新着色一次（2 倍像素密度下实测停顿约 15–30 毫秒），之后每帧只改变光柱的形状、白光的透明度和日间画面的裁切，保持每秒 60 帧；裁切和顶一下的动画设在根元素的过渡伪元素上，每次切换结束都会取消，否则会残留下来，作用到下一次切换的页面画面；这段时间里光柱外的旧画面是静止的，页面也暂不响应滚动。文章页和 404 页没有黑洞，光柱从切换按钮发出；按钮图标和这里的光柱都向另一侧倾斜 18°，让光柱从右上角斜穿页面。系统开启减少动态效果时改为 0.24 秒的淡入淡出；不支持 View Transitions 的浏览器直接切换。链接加上 `?jets=slow` 可以 1/10 的速度慢放。

## 结构

- `index.html` 包含首屏和四个首页章节。构建器更新 `posts`、`archive` 以及各分类取景框内 `catalog-<slug>` 的标记区。分类名称、简介与标本文案在 HTML 中维护。
- `css/style.css`：首屏布局、桌面与移动端适配。
- `css/blog.css`：博客内容、导航、阅读页、404 与移动端适配。
- `css/chapters.css`：首页横向面板、固定场景、顶部导航与底部仪表盘，以及宽屏上仪表两端的折面。
- `css/about-terminal.css`：关于区的档案卡样式：头像与个人主页、字段表格、自我介绍和识别条，以及手机和矮窗口的收紧。
- `css/chapters-vertical.css`：手机竖向首页的版式、渐隐和右侧的高度表刻度带。
- `css/catalog.css` 控制展开后放平的分类面板、正在收起的分类、子分类标题、磨砂文章卡片、空分类的空位卡和返回入口。
- `css/categories.css`：四列分类面板（手机为 2×2），列间以细线分隔。每列顶部是 `//` 与英文标签，下方带角标和点阵的取景框里是一件线框标本：Minecraft 是方块，白日梦话是三道大圆组成的球，神秘文案是三张立着的卡片，其他是八面体。四件标本同一视角、同样 1px 线条，悬空摆放，脚下没有网格地面。悬停或键盘聚焦时镜头微转、标本浮起，再各自展开并亮出一处橙色细节：方块拆成爆炸视图，中心生成橙色核心；球的三道圆环像陀螺仪一样以三种速度散开，一颗橙色卫星开始绕行；卡片像手牌一样展开，前卡的打码文字逐行写出，停在橙色光标；八面体的三个方框各自在平面内转动，重组成立方体的三个中截面，中心亮起橙色节点。离开时所有部件同时归位，减少动态效果时直接到位；取景框变小时标本分档缩小。取景框下是横排名称、两行简介，以及文章数与“浏览”同行的页脚。面板到位时，除面板自身的点亮装饰外，四条标题线也依次点亮；高度不超过 820px 的屏幕收紧间距，使面板完整显示在刻度条上方。标本的悬停与聚焦动效由 CSS 控制。

## Logo

Logo 使用作者在 `logo.ai` 中设计的圆环与斜向尖角图形，保留白色／黑色主体和橙金色内环。网页 SVG 直接提取原稿白色成品画板的贝塞尔路径与遮罩，移除展示用黑底，并提供同形的黑色版本；透明背景，不依赖字体或位图。

| 用途 | 浅色前景，适合深底 | 深色前景，适合浅底 |
| --- | --- | --- |
| 网站 Logo | `assets/brand/gudu-logo-light.svg` | `assets/brand/gudu-logo-dark.svg` |
| 独立图标（同一设计） | `assets/brand/gudu-mark-light.svg` | `assets/brand/gudu-mark-dark.svg` |

## 添加真实文章

Minecraft 文章可嵌入投影或 MicroTimingReplay 红石录制。录制由模组在游戏里直接导出成文章读取的 `scene.json`（录像管理界面的「导出…」或 `/mtr export <录制名>`，模组 1.0.5 起；博客里的 `npm run mc:export` 仍可作备用），导出、写作语法与本地试播见[红石文章指南](docs/redstone-replay.md)。

将 `content/post-template.md` 复制到 `content/posts/`，例如 `content/posts/my-first-story.md`，然后修改开头的信息和正文。一个文件就是一篇文章，不需要按分类建子目录。

```markdown
---
title: 文章标题
slug: my-first-story
date: 2026-10-29
category: 白日梦话
subcategory: 梦境记录
tags:
  - 故事
draft: false
---

这里是文章开头，直接写正文，空一行就是下一段。

## 一个章节

可以使用 **加粗**、*斜体*、[链接](https://gudu.blog/)，也可以写列表：

- 第一项
- 第二项

> 这里是一段引用。
```

- 开头两行 `---` 之间是 YAML 信息，必须包含 `title`、`date`、`category`。值包含冒号加空格等 YAML 特殊字符时请加引号，例如 `title: "观察记录： 一个梦"`。
- `slug` 使用小写英文字母、数字和连字符，对应 `posts/my-first-story.html`，应保持稳定且全站唯一。省略时取文件名去掉扩展名并转为小写；中文文件名需要显式填写英文 `slug`。
- 日期使用有效的 `YYYY-MM-DD`；文章按日期倒序排列，相同日期按 slug 排序。阅读时长根据正文估算。
- `excerpt` 可选，填写时作为首页卡片、搜索和 RSS 的摘要，并显示在文章页标题下方。省略时自动提取第一段文字，最多约 160 个字符；没有段落则从正文提取；自动提取的摘要不会重复显示在文章页标题下。`tags` 是可选列表，也可以写成 `tags: [故事, 记录]`。
- 分类统一配置在 `content/categories.json`：`Minecraft` → `minecraft`、`白日梦话` → `daydreams`、`神秘文案` → `collected`、`其他` → `other`。文章的 `category` 填写对应显示名称；其他名称会保留在文章中，并归入“其他”筛选。标签可自行填写。
- `subcategory` 是可选的子分类名称，构建时去掉首尾空白。省略或留空时取第一个标签，没有标签则归入“未分组”。目录按各子分类最近一篇文章的日期排列，“未分组”始终放在最后。每个子分类里的新文章排在前面。
- 四个分类始终可选，列表计数只包含已发布的文章。暂时没有文章的分类展开后显示空状态。文章页显示子分类，点分类名可直接展开首页的对应列。旧链接（如 `?category=minecraft#journal`）仍会打开最新文章并恢复筛选。
- 搜索匹配标题、摘要、分类和标签，可与分类同时使用。构建会把分类配置和文章元数据一并写入 `js/posts-data.js`，修改配置或文章后需重新运行 `npm run build`。
- `draft: true` 的文章不生成阅读页，也不出现在首页、归档、RSS 或站点地图中。它不是定时发布功能，准备好后改为 `false` 再构建。
- 正文支持标题、加粗、斜体、删除线、链接、图片、嵌套列表、引用、代码块、分隔线和表格。二、三级标题自动生成目录，重复标题会生成不同锚点；只有普通段落的文章也能正常发布。文章标题由开头信息生成，正文建议从 `##` 开始；正文的 `#` 会按二级标题显示。
- 图片建议放在 `assets/posts/` 下，例如 `![图片说明](/assets/posts/my-first-story/scene.webp)`。链接与图片也可使用 HTTPS 地址。相对路径按生成后的 `/posts/文章名.html` 解析，不是相对于 Markdown 源文件；站内图片推荐使用以 `/assets/` 开头的路径。
- 原始 HTML 作为文字显示，不执行脚本；普通 Markdown 排版无需写 HTML。表格和长代码块在窄屏内可横向滚动。
- 旧 JSON 文章仍可继续构建，字段沿用 `slug/title/excerpt/date/category/tags/draft/sections`。`sections` 至少一章，章节含 `title` 与 `blocks`，支持 `paragraph/list/quote/callout/code`。迁移时用同一 `slug` 的 Markdown 替换旧文件，不要同时保留两个同名网址。

写好后执行：

```sh
npm run build
npm run check
```

然后刷新本地预览；尚未启动预览时执行 `npm run dev`。构建会同步首页列表、分类数量、归档、文章上下篇、RSS 与站点地图。删除源文章或将其改为草稿后重新构建，对应的旧生成页也会移除；手写页面不会被清理。不要手工编辑 `posts/*.html`、`js/posts-data.js` 或首页 `posts` / `archive` 标记区域，下次构建会重新生成这些内容。

构建还会给每篇文章裁三份字体：标题、正文和正文粗体（见下方「文章页」的页头和正文两条），放在 `assets/fonts/articles/`。新文章或改过文字时，裁字体需要本机装有 Noto Sans SC 可变字体 `NotoSansSC-VF.ttf`（从 Google Fonts 安装即可；装在别处时用环境变量 `GUDU_ARTICLE_FONT` 指向它）；文字没变时不需要。`npm run check` 只核对每篇需要的字体文件在不在，不需要这个字体。

GitHub Pages 直接发布仓库内的静态文件，因此部署时需要一并提交源文章和生成结果（包括 `assets/fonts/articles/` 里的字体）。关闭 JavaScript 后，已发布的文章列表、归档和正文仍然可读。RSS 地址为 [gudu.blog/feed.xml](https://gudu.blog/feed.xml)。

## 文章页

文章页把首页的 HUD 语言用在边框上，正文本身保持安静：

- 顶栏：文章页和 404 页顶上的 Logo、站名、导航、RSS 和日夜开关和首页顶栏用同一个缩放单位（`--header-unit`：窗口宽 / 1500 和高 / 960 中较小的，夹在 1–1.3px 之间，见 `css/chapters.css`）和同样的尺寸：Logo 46、站名 14、副标 9（最大 10.5px）、RSS 文字 11（最大 13.5px）、图标 17（最大 21px）个单位；首页没有的「文章 归档 关于」用首页顶栏文字的大小。所以两页的顶栏在任何窗口下都一样大（1440×900 时就是这些像素，2000×1125 时约 1.17 倍）；手机保持原来的尺寸。
- 页头：标题用 Noto Sans SC Black（思源黑体最粗的一档），在 Windows 和 Mac 上看起来一样，以首页章节同款的橙色小方块结尾。整套中文字体太大，所以构建时（`scripts/article-fonts.mjs`，用 `subset-font`）只把这篇标题用到的字从 Noto Sans SC 可变字体里裁出来、固定在 900 字重，存成一个 woff2（「测试文章」约 1.5 KB）。每份字体的文件名是「slug-用途-字符哈希」，用到的字不变就不重新生成；字变了会生成新文件并删掉旧的。页面预加载这份字体；字体加载期间标题短暂留空而不是先显示系统字体再跳变，加载失败时退回系统字体的最粗一档。分类、发布日期、阅读时长和标签排成一条「中文 / CODE」字段，上方是关于卡片同款的校准线（橙色起点，每个字段边界一道刻度）；打开页面时校准线划出、四个字段依次落位，约 0.6 秒，减少动态效果时直接显示。
- 背景：星空固定在页面后面，但会按远近回应读者（视差）。向下滚动时观察点跟着下降，星星在文字后面往上走，越近越快：最近的星约为滚动速度的五分之一，远处的按远近递减，最远的几乎不动（换算按窗口高度，任何屏幕上比例都一样）。桌面上移动鼠标时观察点也跟着平移，和首页同一套：向右、向上为正，约 110 毫秒的缓动，鼠标移出窗口后回到中间；近处的星逆着鼠标偏移，最多约 20 像素，远处的不动。触屏只有滚动视差。这两种视差只动星空（`js/article-sky.js`，观察点的升降是 `js/particle-sky.js` 里 `render()` 的 `lift` 参数；鼠标的缓动由 `js/article-parallax.js` 算好，页面其他部分的层次见下面「层次（视差）」）。每颗星都是三维粒子（`js/particle-sky.js`），由 `js/article-sky.js` 透过首屏相机的同一焦距绘制，但没有黑洞和引力透镜：首屏的 24,000 颗之外，还有 48,000 颗密而暗、大多在远处的粒子，取代原来的平面静止星点。它们在屏幕上的亮度与距离无关，多数暗、少数亮，最亮的稍大一点；每档亮度的星数与原来的静止星点接近。观察点绕前方 100 单位处的一点慢慢转（比任何一颗星都近），所以所有星都往左下走：最远的星最快，约每秒五分之一度（900 像素高的窗口里约 6 像素），最近的约为其三分之一。日间是负片并压到 40%，暗星的透明度按亮度的 1.6 次方取，免得白天的星比夜里显得密；标签页隐藏时暂停，减少动态效果时停在初始位置，也没有视差。

- 正文字体：正文连同小标题、标题下的摘要、回放下方的图注和文末「本文完」那句，都用思源黑体（Noto Sans SC）。汉字和中文标点来自这篇单独裁出的两份字体，常规（400）和半粗（600，小标题和加粗共用）；英文和数字仍是 Segoe UI（Mac 上是系统字体）。「测试文章」的正文用到 434 个字，常规约 60 KB，半粗约 5 KB。两份字体都预加载，先用系统字体显示，到了再换；汉字每个都占一个字宽，所以换字体时行不会变。思源黑体自带标点挤压，像「，《」这样挨着的标点会自动收紧。由脚本写出的字不在裁出的字体里，所以仍用界面字体：红石回放的界面、代码块的「复制」按钮、文末的「复制文章链接」；代码里的字也不裁（代码是等宽字体）。文章页自己的部件也用这套字体，所以一页上只有一种中文字体：返回文章列表、页头字段、目录、上一篇 / 下一篇和页脚的字一起裁进这两份字体（加上这些后「测试文章」的常规约 66 KB、半粗约 8 KB）。顶栏和首页共用，仍是界面字体；评论区由评论脚本写出，也是界面字体。

## 读者评论

文章页已准备 Waline 评论接入：昵称必填、邮箱选填，无需注册；评论审核后显示。`content/comments.json` 的 `serverURL` 默认为空，此时不显示评论区，也不请求评论服务。部署好独立服务后填入地址并重新构建即可启用，操作见 [评论服务部署步骤](docs/comments-deployment.md)。

单篇文章可在 YAML 中设置 `comments: false`；示例文章不加载评论。评论按 `/posts/slug.html` 区分，改标题不会丢失关联，已发布的 `slug` 应保持不变。本地与其他预览域名不连接正式评论服务；评论组件只在接近评论区时加载，客户端脚本与样式随网站本地发布。

`services/comments/` 提供独立 Vercel 服务模板和服务端昵称校验，数据库与管理员账户尚需按部署文档创建。数据库密码、邮件密码、Turnstile secret 等只保存在评论服务的环境变量中。邮箱通知需要另行配置 SMTP。

## 黑洞视觉

首页采用实时 WebGL 3D 黑洞渲染，默认保持极简主题。`js/black-hole.js` 按相机方向积分光线，生成倾斜吸积盘、中心暗影及弯曲光弧；暖白与淡琥珀色的细线成组聚散并持续流动。鼠标位置参与相机参数，盘面与光弧会随实际观察方向变化。背景有两层星空：场景下方一层清晰的平面星点，以及着色器里随光线偏折的少量星点；不绘制银河带。着色器采用有限步长的视觉近似，重点是构图、空间关系与动态效果。

打开文章目录时，相机跟着分类面板向上仰 50°（`setPitch`）：星空按仰起的相机转下去，黑洞不随广角透视拉长，保持原样整体滑下，越近画面边缘越快，约 0.6 秒后完全离开画面底部；透镜对星光的偏折跟着黑洞走。平面星点没有相机，整层同步下移，速度与画面上半部的星点一致，循环周期里的星从上方补进来。没有 WebGL 时回退图下移同样的距离。关闭目录时原路转回；减少动态效果时直接到位，手机竖向首页不转动。

着色器里的极简星空全部由 `js/particle-sky.js` 中 24,000 颗固定种子的三维粒子组成，每颗星保存真实 XYZ 坐标、物理尺寸与亮度。外观参照 10 月 4 日初版星空：采用相同的冷灰白色 `rgb(193, 204, 223)`，以细小星核和暗背景留白为主。距离连续分布，近星自然有更明显的透视和鼠标视差。观察点绕前方 100 单位处的一点慢慢转（比任何一颗星都近），星点因此都向左下移动，越远越快：最远的约每秒五分之一度，最近的约为其三分之一；保持当前 1.50 倍活动时间系数，运动复用场景活动时钟，鼠标只添加观察位置偏移。离屏、后台及减少动态效果时暂停。星群在大范围内逐颗循环，边界完全淡出后才换位，没有全景时间重置或刻意的明暗闪动。

密集星点由 `js/star-sky.js` 生成星表，首屏和各章节共用：按舞台面积每 2500 平方像素一颗（120 到 1400 颗，2560×1370 以内的窗口都保持这一密度），固定种子，位置、大小、亮度和远近各不相同，成片聚散并留出暗区，夜间为冷灰白、日间为反色、水墨为暖白。极简主题下它们是 GPU 粒子（`js/star-field.js`，画在场景下方的 WebGL 画布上）：每颗星的圆点按画布原生的抗锯齿事先取样，所以静止时与原来的二维画布逐像素一致（每通道误差不超过 2/255）。它们和着色器里的粒子一样绕前方一点慢慢向左下漂：远处的星最快（900 像素高的舞台上约每秒 6.2 像素，按舞台高度缩放），最近的约为其三成，在舞台四周 6% 的余量里循环，换位发生在画面外；漂移用场景的活动时钟，减少动态效果时不动。水墨主题和没有 WebGL 时仍由 `js/main.js` 画在二维画布上，保持静止；两条路径切换时星点停在当时的位置接着画，不会跳动。鼠标移动时远处的星随画面平移几个像素，近处的星略微反向；着色器里星点随鼠标的位移实测也只有 0–3 像素，两层保持同步。日间进入章节时，星点随章节进度淡到四成，避免深色小点在浅色面板旁像灰尘；首屏和夜间不变。黑洞的阴影和盘面遮住它后面的星；时钟那一行周围的星调暗到 15%，避免亮点落在数字之间被看成标点。没有 WebGL 时它同样画在回退图下方。404 页用同一片星空作静止背景，随日夜切换重画。进入章节后黑洞整体降到六成亮度：面板之间的缝隙露出的黑洞与面板后面透出的部分亮度接近，不再被切成明暗两截。

粒子使用一个 GPU 点精灵批次投影到方向光照纹理；前方分配更多角度分辨率，仍保留完整球面供强偏折光线采样。星空纹理在初始化时按绘制宽度选用 1024×1024 或 2048×2048，含 mipmap 分别约占 5.3 或 21 MiB，顶点缓冲只上传一次。接缝留有余量并复制边缘星点；收小较亮星的物理半径，使用单层紧实高斯星核，取消额外光晕，保留亚像素重建过滤与能量补偿。光线采样使用解析纹理梯度、mipmap，以及支持时最高 4 倍各向异性过滤，减轻闪烁并保留透镜拉伸星像的细边。

极简背景直接使用积分得到的逃逸方向：取消冲击参数 3.5 到 7 之间混回直线的美术压缩，也取消 `h² > 140` 的直线捷径，避免成像被压缩或在旧阈值产生接缝。吸积盘交点和水墨主题保持既有计算。模型仍使用最多 180 步积分、半径 42 的逃逸边界和无自旋 Schwarzschild 近似；星空仍作为无限远方向背景采样，并非完整的有限距离光源或精确广义相对论模拟。

星群与暗区交错，取消冷暖环境雾光，不绘制银河带；星空的泛光依据覆盖率与光强之差单独抑制，保留不透明吸积盘的泛光。中心阴影与盘面继续遮挡星光，透明盘缘能透出后方背景。标题暗区按实际标题位置计算，水墨主题继续使用原有背景。粒子绘制、过滤及黑洞渲染共用完成检测与绘制预算，退出时统一释放资源。扩展画布保留原来的虚拟相机画框，黑洞的尺寸、位置和俯仰不变。

极简主题的桌面画框统一按首屏实际高度的 1.85 倍设置，中心位于首屏高度的 57%，以宽屏确认的构图为基准；较窄的桌面窗口不再受 1760px 宽度上限影响，也不会在 16:10 分界处突然缩小、下移。窄窗口内横向位置逐渐右移，给标题和吸积盘左端留出空间。画框保持 3:2；平板与手机继续使用各自的尺寸规则。

外缘的暖白薄光适度加宽、提亮，通过柔和光肩融入盘面，近侧亮度更轻。盘边通过覆盖率渐隐，并继续追踪、合成后方光弧，避免暗淡但仍不透明的外层形成黑带；透明过渡集中在最外侧，减少前后细线重叠的区域。俯仰朝扬起方向调整，保持原来的画面倾角。

细线按屏幕两轴的像素频率与实际线宽过滤。可分辨的线条保留覆盖积分；压缩线条使用正值、归一化的 Fejér 核和轻量 Gaussian 滤波，在 0.48 周期/像素前截止，最多计算 16 个谐波并按带宽提前退出。过滤结果不再硬裁切，防止负值振铃被裁切后重新产生高频。发光背景与亮线分别做色调映射，再按覆盖率混合，防止对平均亮度施加非线性曲线而重新制造条纹；极简盘面曝光保持 1.80，亮线核心更清楚，盘面底光与首屏辉光适度减弱。极简中心高阶像和检测到的材质轮廓局部采用八光线采样，水墨保留四光线；子光线跨越不同像层时重新计算对应表面的采样范围。辉光保留先低通再缩小的处理，纹理坐标使用高精度。上述调整不增加渲染通道或全屏多重光线追踪。

极简线束保留原来的数量和疏密分组，叠加轻微、连续的曲率与线宽变化，并在形变进入细线相位前按像素范围过滤。三个局部亮纹沿不同半径旋转，错开淡入、淡出；每段生命周期为 24 秒，完全熄灭后才重置，避免长时间差速旋转把纹理卷成无法分辨的噪点。弧形高光使用四阶谐波过滤，通过递推复用三角函数和指数计算；径向过滤保留总能量，只跳过小于约 0.00004 的远侧尾部，整体明暗分布与局部流动分开。动画继续使用活动时钟，鼠标只影响视角，暂停期间不补算轨道时间。

鼠标视差使用约 110 毫秒时间常数的平滑，标题等轻量图层每次显示刷新都更新。首屏相机仍在跟随输入时，有 GPU 完成检测且未降档的渲染器请求最高 60 帧，静止后回到默认 30 帧；低性能设备继续遵守原有降档与单帧在途限制，不因交互强制降低清晰度。帧调度保留跨刷新的小数余量，兼容 60、75、120、144 Hz；显卡繁忙时保持旧画面，待完成后的下一次刷新绘制当前视角，不消耗空的绘制周期或积压历史鼠标事件。

默认优先使用 WebGL 2，以零超时的 `clientWaitSync` 检查整帧完成信号，不读取 GPU 时间戳。上一帧尚未完成时保留已显示画面并稍后重试，粒子、mipmap 与黑洞共用这一限制；没有计时扩展也不会无条件提交新帧。可见时每次动画回调都检查完成信号，绘制则按独立帧率调度。未完成轮询给出耗时下界，从提交开始到确认完成的时间给出保守上界；使用连续 8 帧的中位数判断负载。暂停、切换主题或超过 250 ms 的轮询间断会清空采样与恢复计时，保留限制提交的 fence。WebGL 1 兼容路径保留计时扩展检测；没有该扩展时使用较低像素预算及帧间隔采样，不根据 JS 提交速度猜测 GPU 恢复能力。

WebGL 2 的渲染宽度最多 3200 像素，设备像素比最多取 2，初始像素预算最多 370 万，可覆盖原生 1080p、1440p 及部分高密度屏幕。WebGL 1 保留 2400 像素宽度、1.5 倍设备像素比，根据计时扩展能力采用 180 万或 90 万预算。所有路径都受设备的 `MAX_TEXTURE_SIZE` 限制。

有 GPU 完成信号或计时扩展时，持续超载会优先降低内部渲染尺寸，保留 30 fps 的目标节奏。每次根据耗时降低 10%–25%，最低为目标尺寸的 60%，调整间隔至少 750 ms；达到下限仍超载，才降至 20、15 fps。确认连续 5 秒有足够余量后，先恢复帧率，再每次恢复 5% 尺寸，恢复间隔至少 2 秒。恢复判断会按下一档像素面积估算耗时，并保留余量，避免反复切档。没有计时能力的 WebGL 1 保留更保守的帧率优先策略。尺寸变化只在上一帧完成后的下一次绘制前生效，尺寸未变时不重新分配纹理；构图、光路与活动时钟的速度保持不变。画布始终保持显示分辨率，降档只缩小离屏渲染纹理，由合成通道放大输出；调整画布尺寸和检查帧缓冲完整性都要等待 GPU 进程，在章节切换动画期间会让页面停顿数十毫秒。帧缓冲完整性只在首次分配时检查。

内容章节开始横移时，若渲染器已经降低画质或帧率，或上一帧持续繁忙，暂时保留黑洞背景并停止它的动画回调，把 GPU 余量留给面板合成。横移结束后继续绘制，不补算暂停期间的轨道时间；首屏与内容区之间的黑洞相机转场仍正常播放。章节仅在活动开始、类型切换与结束时通知背景，不增加逐帧事件或额外计时器。

极简与水墨使用按主题专门编译的着色器，编译期常量移除另一主题的光线和材质分支。只在首次选择某个主题时异步编译并缓存，快速切换时串行构建并仅激活最后请求的主题；只访问水墨时不创建粒子星空的程序、几何和图集。关闭、刷新或上下文丢失会取消编译轮询并使旧任务失效。

页面隐藏或场景离屏时暂停持续绘制；首页章节模式下场景固定在视口内，进入内容区后继续绘制。系统减少动态效果偏好下保留静止画面，移动端仅在章节边界接管单指竖向滑动。普通页面退出会取消初始化轮询和绘制重试，并屏蔽迟到回调；关页路径不再调用 WebGL，包括逐项删除 GPU 资源，交由浏览器在销毁文档时回收上下文，避免退出处理再次进入忙碌的显卡驱动。仍在使用的页面若主动销毁渲染器，普通 `dispose()` 继续释放其资源。进入浏览器往返缓存时只暂停，返回后继续。加载器在退出时静默清理，恢复可见后才通知页面就绪；章节布局忽略离开页面后的尺寸变化和迟到通知。WebGL 不可用，或 WebGL 1 缺少着色器导数扩展时，显示当前主题对应的 `assets/black-hole-minimal-fallback.png` 或 `assets/black-hole-ink-fallback.png`，两张图均由对应实时材质画面导出。极简回退图的外围留白做透明渐隐，避免窄屏显示出星空画框的矩形边界。关闭 JavaScript 时显示默认极简回退图。

东方水墨主题使用三维光线追踪：光线与由 `inkHeight` 定义、略有起伏的盘面相交，再读取从原参考图提取的极坐标材质。同一图集的不同通道分别保存前盘、上方光弧与下方副像的笔触；配套明暗图将整体光照分布与流动笔触分开，保留原画的明暗构图。透明盘边继续追踪并合成后方光弧，避免边缘截断产生黑带。盘面飞白与外围三维点墨共同形成不规整的水墨轮廓；这是依据原画制作的视觉重建，不保证像素级复刻或严格的物理模拟。极简模式继续使用原有渲染方式。

水墨笔触和点墨以每秒 0.12 弧度连续单向旋转，约 52.36 秒一周。独立的单调活动时钟推进轨道相位，帧率与鼠标输入不改变转速；隐藏、离屏或减少动态效果时冻结，恢复后不补算暂停时间。水墨鼠标视差保留相机俯仰、画面倾转与平移，取消绕盘面法线的方位角变化，避免观察角变化叠加出转速改变的观感。动画不使用整张参考图的往复形变。

材质通过 mipmap 与 WebGL 2 原生纹理导数采样（WebGL 1 使用 `EXT_shader_texture_lod`）减少压缩笔触的锯齿和闪烁；水墨所需的扩展不可用时显示水墨回退图。运行时同时加载 `assets/black-hole-ink-material.png` 与 `assets/black-hole-ink-light.png`，原图仅用于离线烘焙。

需要从原图重新生成材质时，使用 Node.js 22 或更新版本，先启动本地预览，并准备已开启 Chrome DevTools Protocol（CDP）、调试端口为 9243 的 Chrome/Chromium，再执行：

```sh
node scripts/bake-ink-material.mjs --site http://127.0.0.1:4173 --port 9243
```

脚本读取原参考图与当前渲染器的盘面几何，生成 `assets/black-hole-ink-material.png` 和 `assets/black-hole-ink-light.png`，保留原图不变。它使用已有浏览器连接，不会启动浏览器，也无需安装额外依赖；材质烘焙仅手工执行，不随 `npm run build` 或 `npm run check` 运行。

水墨首屏局部采用近黑炭纸背景、暖白文字与低调纸纹，文章区域和全站导航保持现有样式。直接打开 [水墨预览](http://localhost:4173/?blackhole=ink) 或 [极简预览](http://localhost:4173/?blackhole=minimal)，也可以在部署地址后使用相同参数。有效的 `blackhole=ink` / `blackhole=minimal` 参数优先于日期配置，未知参数值按正常日期规则处理。水墨两张纹理均加载就绪后开始实时绘制；加载期间或任一加载失败时显示水墨回退图。

特殊日期在 `js/black-hole-theme.js` 的 `config` 中设置：

```js
const config = {
  timeZone: 'Asia/Shanghai',
  fixedDates: [],  // 单次日期，填写 YYYY-MM-DD 字符串。
  annualDates: [], // 每年日期，填写 MM-DD 字符串。
};
```

日期按北京时间（`Asia/Shanghai`）判断，与访问者本地时区无关；固定日期或每年日期任一匹配即使用水墨，其他日期使用极简。每年 `02-29` 仅在闰年对应日期生效。目前两个列表均为空，尚未设置自动切换日期。页面每分钟以及恢复可见时重新判断，切换会同步实时材质、回退图与无障碍描述；首次加载在首帧前确定主题。没有额外的页面主题控件。

`assets/black-hole-minimal.png` 及本地风格画廊中的图片作为构图参考保留；水墨原图仅作为上述离线材质烘焙的来源。画廊展示的是静态概念图，可通过其中的首页链接查看实时效果。旧版金色静态图 `assets/black-hole-static.png` 继续保留，原有 `js/black-hole.js` 已改造成当前渲染器。

时钟采用访问者设备的本地时区，每秒读取真实时间；与视觉动画独立更新，返回页面时立即校时。

首屏入场与加载幕布揭开同时开始，分完整版和短版。完整版由 `js/intro.js` 编排，每个浏览器会话（同一标签页）播放一次，访客手动刷新时再播一次：幕布揭开后先只有星空，镜头从标题所在的左上方天区向后拉，黑洞从对角一侧扫入画面，边缩小边滑到主视觉里的位置，约 1.2 秒落定；随后背景英文浮现，橙色句点作为光标逐字打出中文标题，时钟数字滚动后锁定到当前时间，四角定位标淡出。从幕布开始揭开到全部落定约 1.9 秒。播放中滚动、点击、触摸或按键会直接跳到落定画面；进入章节、切换主题、页面隐藏或离开时同样立即结束。

镜头只改变交给着色器的取景范围：围绕舞台外的一个固定点把画面放大 1.8 倍再逐步收回，着色器与相机参数不变，吸积盘在任何倍率下都按原生分辨率绘制。固定点位于舞台左上角与黑洞连线的延长线上，距离按盘面的外接椭圆求出，保证开场画面里没有黑洞，又不会退得更远。开场的星空就是首页平时的密集星点（见“黑洞视觉”）：入场期间它随镜头一起放大，每颗星按自己的远近分担镜头的行程，后拉时向同一个固定点收拢，移动时留下一帧的拖痕；黑洞落定时每颗星正好回到平时的位置，不淡出，也不消失。

短版约 0.5 秒，只用 CSS，不依赖脚本：黑洞渐显，背景英文浮现，中文沿水平边界揭开，句点和时钟收尾。同一会话里从其他页面回到首页（点链接或后退，不含刷新）、实时场景不可用（显示回退图）、显卡太慢、页面不在顶部或地址带章节锚点，或入场脚本未运行时使用短版。浏览器刷新时会恢复上次的滚动位置，离顶部几像素以内仍算首屏，不会因此退回短版。系统减少动态效果偏好下直接显示最终排版。“显卡太慢”由渲染器自己的 GPU 计时判断：幕布揭开后、镜头开始移动前（只有星空的 0.46 秒里），取最近三帧的中位数，按渲染器可接受的最低画质 0.6 换算，仍超过 33 毫秒（达不到每秒 30 帧），或渲染器已经主动降低了帧率，就在镜头动起来之前改播短版；带计时的场景在这段时间里拿不到三帧数据时同样改播短版。这种情况不记作“已看过完整入场”，下次刷新会重新判断。`?intro=full` 与 `?intro=slow` 始终播放完整版。链接加上 `?intro=slow` 以五分之一速度播放完整版，`?intro=full` 重播完整版，`?intro=short` 强制短版。文字入场与鼠标视差使用独立的变换；入场结束或离开页面后不重复播放。

“个人博客”右侧的红色方块在入场结束后按固定 1 秒周期连续闪动：亮 0.5 秒、灭 0.5 秒，由 CSS 动画循环控制。离开首屏、隐藏标签页或启用减少动态效果时暂停并恢复常亮，返回后从亮起状态重新开始。

开场加载页直接使用作者 Logo 的原始 SVG 路径：细白线先从左下向右上加速勾勒斜向部分，再接入顺时针展开、逐渐减速的圆形部分。两段交接重叠 90 毫秒，避免衔接停顿；白色填充沿相同的速度曲线落后轮廓 140 毫秒跟进，约 0.93 秒形成完整标识。橙金色内环晚一点起笔，逆时针加速后柔和收尾，前后两层共用一个揭示遮罩，描边接点放在被 Logo 遮住的右上方；完成后保持纯金色静止，不叠加浅色流光。轮廓与填充复用同一原稿路径，保留 Logo 形状与金环交错层次；SVG 内联于首页，不需要额外下载图片或动画库。Logo 四周有四个定位角标，各自从拐角向两边画出。下方是三行等宽字读数 FONT、SCENE、FRAME，约 0.4 秒后依次淡入，分别对应标题字体、场景编译和首帧（没有实时场景时为回退图解码）：正在等待的一行闪烁橙色方块，完成后显示 OK，设备无法运行实时场景时 SCENE 显示 `--`。读数只反映真实进度，不显示虚构百分比；“正在载入”保留为读屏文字。完整标识至少停留约 0.17 秒后开始退场。

加载页等待字体与黑洞首帧就绪后退场：Logo 与读数先淡出，四个定位角标向外展开到首屏边框的四角，幕布随后揭开，全程 0.42 秒；退场开始即播放首屏入场，不等幕布完全消失。完整入场时，黑洞在幕布后绘制的首帧已经是开场的星空画面，幕布揭开时不会闪出最终构图。当前主题回退图同时解码，实时渲染初始化失败时使用它。正常情况下自 Logo 动画开始至少展示 1.1 秒。准备过慢时约 3.45 秒启动退场，4 秒强制放行，资源或过渡事件挂起均不会继续锁住页面。关闭 JavaScript 时直接显示页面与回退图；减少动态效果时显示完整静态 Logo、首帧或回退图就绪后直接放行。后台与退出时静默释放，恢复可见后再通知页面。

WebGL 初始化提前到加载幕布期间：先给 Logo 勾勒约 1.1 秒，再编译材质并绘制静止首帧。支持 `KHR_parallel_shader_compile` 时轮询非阻塞的编译完成状态，再读取链接结果与 uniform；提交首帧后通过零等待的 GPU 完成检测通知加载器。正常情况下幕布开始淡出时黑洞即可响应，不再等待标题入场结束。超时先放行回退图，迟到的实时材质仍可替换它；编译失败或上下文丢失时保留静态画面。减少动态效果时准备同样的首帧，但不启动持续动画。

## 检查

```sh
npm run check
```

检查包含 JavaScript 语法、生成文件与文章源的一致性，以及文章生成、主题日期、动画计时、渲染器启动、帧调度和粒子几何的自动化测试。计时测试覆盖慢帧、连续鼠标输入、暂停恢复、分档帧率、加载期间准备首帧与高负载滑动暂停；加载测试覆盖首帧等待、失败回退、软硬超时、页面恢复，以及读数只跟随真实进度；入场测试覆盖完整播放的时序、每会话一次、刷新重播与 `?intro` 参数、各种输入与页面状态下立即落定、无法开场时退回短版，以及帧循环停滞或出错时的收尾；慢显卡测试用模拟的 GPU 计时确认快场景照常播放、慢场景在镜头移动前改播短版且不记作已看过、计时不足时不冒险移动镜头，以及 `?intro` 参数仍然优先；星空测试覆盖固定种子、密度与上限、三种色调、404 页的静止星空随尺寸与主题重画、首屏星空在章节中按日夜淡出、时钟一行附近调暗，以及首屏 SCROLL 提示只在离开首屏后消失；手机竖向测试另外在真实浏览器里确认章节链接落在该章、分类筛选行独立横向滑动并渐隐；启动测试覆盖按需异步编译、快速切换、缓存复用、上下文恢复、编译失败与扩展缺失；渲染测试覆盖零超时完成检测、繁忙时保留画面、资源释放、原生分辨率、优先降低像素成本以及带冷却和保守耗时预测的恢复，并确认入场镜头只改变取景范围、开场画面不含盘面、且与着色器的投影一致。提示生成文件过期时，先执行 `npm run build`。测试不向网站添加文章或修改视觉资产。

主题检查确认样式里的每个颜色都写明日间与夜间值；主题脚本默认夜间、恢复已保存的选择、预览参数不改写选择、存储不可用时仍能切换；各页面在样式表之前设好主题，每个 Logo 都配有日间版本，首页的黑色球体是带标签的切换按钮，且只在主视觉可用；日间调色保持纸色、品牌橙与阴影规则，文字对比度不低于设定值。渲染检查另外确认日间反转吸积盘、阴影与星空的颜色（阴影变成纯白，水墨保持黑色），并且只跳过泛光绘制。光柱检查用模拟时钟和模拟的 View Transition 验证完整的切换与切回、中途反向后换回原配色并等待黑洞重绘、收尾时的再次点击、浏览器跳过过渡后仍落到所选主题、减少动态效果与不支持时的退化，以及光柱的起点、倾斜方向、实心白色、整屏白光后日间页面浮现、切回时先褪成白色、射出时夜间画面以黑洞为中心顶一下，每次切换结束时取消自己的裁切和动画，使切回夜间后再切到日间时光柱外仍是夜间画面；渲染检查还确认交给动画的相机与着色器把页面像素换算成屏幕坐标的方式完全一致。

细线采样检查直接执行着色器中的标量计算，验证多种线宽、像素尺度和方向下的覆盖范围、平均亮度、频谱截止与清晰线条保留，并检查色调映射后的亮度对覆盖率保持线性；局部亮纹检查覆盖生命周期衔接、角度接缝、长时间运行和过滤后的平均亮度。此检查不替代浏览器中的光路导数、浮点精度和最终合成验证。

透镜检查从着色器提取实际光路积分与天空方向变换，在 CPU 上验证旧截断处连续性、完整环状成像、远场偏折、方向旋转，以及盘面遮挡和水墨兼容性。它验证当前模型的行为，不作为精确广义相对论基准。
